# Tech debt

- **Alert webhooks on a non-443 port are refused** (`src/lib/alerts.js` uses the scanner's strict `checkUrl`). A self-hosted ntfy on `:8443` can't be used. Fix: a separate, perchlight-hooks-style rule set for owner-configured webhook URLs (ports allowed, private ranges still refused). Found while building v0.1 (2026-11-12).
- **A "Try again" on an alert whose claim was pruned (older than 30 days) stays `retry_requested`** in D1 and is re-read (at most 20 rows) on every scan start. Harmless; fix: mark such rows `failed` with "too old to retry" in `startDue`.
- **The report session cookie is a static HMAC of the admin token** (`src/routes/report.js`): its 8-hour life is enforced only by `Max-Age`, it can't be revoked short of rotating `ADMIN_TOKEN`, and `/r/login` and the API have no rate limit. Acceptable for a personal tool (16+ character token, constant-time compare). Fix: a timestamped, signed session value checked server-side; a WAF rate-limiting rule on a custom domain. From the v0.1 review (2026-11-12).
- **CSS carry-forward is all-or-nothing** (`src/scanner.js` finalize): when any one stylesheet fails or is skipped, every tracked CSS-derived ("via ...") finding is carried, so a finding from a stylesheet that was read fine resolves one scan late. Fix: track the failed CSS paths and match `evidence.startsWith("via <path>:")`. From the v0.1 re-review.
- **Stylesheets beyond the first 5, or out of scope, aren't read** and don't mark CSS as incomplete, so findings from them (if the set of linked stylesheets changes order) can be resolved by the normal 2-scan rule. Fix: a stable order (sorted by URL) and a per-scan cap note. From the v0.1 re-review.
